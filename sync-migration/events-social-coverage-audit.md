# Events and Social: remaining sync coverage

Reviewed 2026-11-12 against Events `770e43f8baaf47844bf4ff5768e5493a380508bc` and social-service-ea `143e9aa3c2fe21c9e44e9541e7c8dc2561a9d1ec`. These are local source revisions, not verified deployed revisions. The inventory covers repository writers; operator SQL, cloud schedules, queue configuration and deployed grants still need staging confirmation.

**Decision:** rehearse the existing schedule/settings adapters first. Expand Events as a coupled event-and-attendance projection, and Social as complete relationship/community aggregates. Copying isolated additional tables is insufficient for public reads or authorization. Keep production as the only job, queue and provider owner.

## Events scheduled jobs

[Server registration](https://github.com/decentraland/events/blob/770e43f8baaf47844bf4ff5768e5493a380508bc/src/server.ts#L37) runs three notification jobs and recurrence every minute; foundation addresses refresh every five minutes.

| Job | Writes/effects | Rehearsal implication |
| --- | --- | --- |
| `updateNextStartAt` | [Recurrence expansion](https://github.com/decentraland/events/blob/770e43f8baaf47844bf4ff5768e5493a380508bc/src/entities/Event/cron.ts#L23) updates `events` recurrence dates/next occurrence. | Outside schedule capture. Future Events coverage must execute this real job against fixtures and verify its committed row changes; target recurrence stays off. |
| Upcoming, started and ended notifications | [Notification jobs](https://github.com/decentraland/events/blob/770e43f8baaf47844bf4ff5768e5493a380508bc/src/entities/Event/cron.ts#L51) publish SNS, upcoming Slack, and advance `notification_cursors`; started events can fetch Social community members. | Copy event facts only. Cursor equality is not proof of delivery. Duplicate target execution could notify twice or alter Social ranking twice. |
| `refreshFoundationAddresses` | [Feature-flag refresh](https://github.com/decentraland/events/blob/770e43f8baaf47844bf4ff5768e5493a380508bc/src/modules/decentralandFoundationAddresses.ts#L31) updates process-local cache. | Not DB replication; public read equivalence also depends on configuration/cache behavior. |

**Source defect found:** recurrence calls `EventModel.update(...)` without awaiting it in [cron.ts](https://github.com/decentraland/events/blob/770e43f8baaf47844bf4ff5768e5493a380508bc/src/entities/Event/cron.ts#L47). The job can report completion before the write finishes and cannot catch that promise's rejection through its own lifecycle. A separate Events fix should await the write and verify failed-write propagation before using that job's completion as rehearsal evidence. Capture still observes any successful commit; this is not a defect in the current schedule mapper.

## Social jobs and internal traffic

- [Daily community ranking](https://github.com/decentraland/social-service-ea/blob/143e9aa3c2fe21c9e44e9541e7c8dc2561a9d1ec/src/components.ts#L287) writes scores after reading communities/metrics; initial execution waits 30 minutes. Its outputs are not settings facts.
- [Private voice expiry and community polling](https://github.com/decentraland/social-service-ea/blob/143e9aa3c2fe21c9e44e9541e7c8dc2561a9d1ec/src/components.ts#L326) expire call rows and publish updates, or query Gatekeeper and update the voice cache. Neither should start in the follower.
- [SQS handlers](https://github.com/decentraland/social-service-ea/blob/143e9aa3c2fe21c9e44e9541e7c8dc2561a9d1ec/src/controllers/handlers/sqs/handler.ts) consume login, event-ended, photo and streaming messages. Running another consumer/processor is not equivalent to safely duplicating its source outcome.
- [Peer synchronization](https://github.com/decentraland/social-service-ea/blob/143e9aa3c2fe21c9e44e9541e7c8dc2561a9d1ec/src/adapters/peers-synchronizer.ts) and [subscriber reconciliation](https://github.com/decentraland/social-service-ea/blob/143e9aa3c2fe21c9e44e9541e7c8dc2561a9d1ec/src/adapters/rpc-server/subscribers-context.ts) maintain Redis/presence and live subscriber state. They are separate from durable PostgreSQL synchronization.

## Ordered next work and repository changes

1. **Rehearse implemented scopes:** install source capture and explicit writer/runtime grants; test real source handlers, no-op writes, deletes, restart and reconciliation. Prove provider credentials and target jobs remain absent. Neither Events nor Social needs an application PR for these adapters.
2. **Fix the Events recurrence await defect separately:** this source PR has a job-lifecycle reason, not a requirement to add sync calls to every writer.
3. **Add event + attendance + referenced schedule facts together:** extend the existing Events source adapter with a new reviewed generation/baseline, not another competing source owner. Begin with non-community events and complete place dependencies; community events require Social aggregate coverage. Test source recurrence and RSVP-counter intermediate commits explicitly.
4. **Add Social mute facts, then relationships:** extend the source capture contract with composite scope keys and coordinated baselines. Preserve target jobs/provider inactivity. The current `social-settings` adapter must not become an overlapping writer for a broader Social adapter.
5. **Add community aggregates and rank outcome policy:** capture role/ban/request changes, posts and metrics with explicit dependencies before community events or permission-sensitive reads. Keep provider enforcement and WebSocket notifications as separate activation gates.

Each fact-only expansion requires dcl-one mapping/tests and reviewed source DB capture changes, not source HTTP/RPC modifications by default. A source application PR is justified only by a concrete source bug, an atomicity requirement not satisfied by its existing commits, or an explicitly selected native replay/effect protocol. No deployed installations, load tests or live-job runs were performed for this audit.
