# 场景元数据

场景是一个在空间上有界限、并映射到一个或多个地块的 Decentraland 项目。如果场景部署到一个 [世界](/docs/creator/content-creator-zh/chang-jing-sdk7/fa-bu/publishing-options/#decentraland-worlds)，玩家可以通过 URL 访问它。

参见 [场景中的文件](/docs/creator/content-creator-zh/chang-jing-sdk7/xiang-mu-lei-xing/scene-files/) ，查看场景项目中使用了哪些文件的列表。

## 元数据

要在以下位置编辑场景的元数据： [Creator Hub 中的场景编辑器](/docs/creator/content-creator-zh/chang-jing-bian-ji-qi/ru-men/about-editor/)，打开一个场景并点击 **铅笔图标**.

![](/docs/_remote/a64bc0ae30e4d852f97ccd78.webp)

这会打开场景菜单，你可以在其中配置多个属性。

![](/docs/_remote/c3618719dd688d071c5d267b.webp)

或者，你也可以直接编辑 `scene.json` 文件，所有这些值都存储在其中。


> [!WARNING]
> **📔 注**：不要向 `scene.json` 文件中添加本页未提及的自定义字段，因为这可能导致加载场景时出错。


## 场景标题、描述和图片

为你的场景提供标题、描述和缩略图非常重要，这能吸引玩家并帮助他们了解可以期待什么。

当玩家在地图上选择你的场景地块时，会在模态窗口中看到这些内容。当他们被 [传送](/docs/creator/content-creator-zh/chang-jing-sdk7/jiao-hu-xing/external-links/) 到那里，由另一个场景传送过去。将这里设置得更有吸引力的数据，可以显著帮助为你的场景带来流量。

当玩家在世界中导航并进入你的场景时，他们可以从小地图下方看到场景标题。

![](/docs/_remote/0e2898c7018cc52a2d72b72d.webp)

可通过场景编辑器中的场景菜单添加这些数据。

如果你希望其他开发者能够联系到你，也可以为你的场景添加联系信息。


> [!NOTE]
> **📔 注**：World 会保留自己的名称、描述和缩略图，与场景的元数据分开。如果一个 World 只包含一个场景，则每次发布时 World 的元数据都会根据场景的元数据更新。如果它包含多个场景，World 的元数据是独立的，并且只能在 **管理** 选项卡中进行编辑。参见 [World 元数据与场景元数据](/docs/creator/content-creator-zh/chang-jing-bian-ji-qi/fa-bu/publish-scene/#world-metadata-vs-scene-metadata).


### 场景缩略图

缩略图设置在 `navmapThumbnail` 字段中。它必须是一个 *.png* 或 *.jpg* 图像，具有 **16:9** 的宽高比。 *1920x1080* 像素是建议目标尺寸。只要保持相同的 16:9 比例，其他尺寸也可以。

平台的某些部分会显示缩略图的缩小方形版本，裁剪到中央的 *1080x1080* 像素。请将文本或徽标等重要内容保留在该安全区域内，以免被裁切。


> [!WARNING]
> **📔 注**：Creator Hub 会拒绝不是 16:9 的图像。如果你将 `navmapThumbnail` 手动设置为其他形状的图像，显示它的客户端可能会以不可预测的方式拉伸或裁切它。参见 [场景缩略图](/docs/creator/content-creator-zh/chang-jing-bian-ji-qi/pei-zhi/scene-settings/#scene-thumbnail).


![场景缩略图安全区域：完整的 1920x1080 图像，其中中央 1080x1080 方形标记为安全区域，左右两侧带状区域标记为裁切区域](/docs/_remote/a4fca710bad41737e2da1248.webp)

上的图像 `navmapThumbnail` 应为项目文件夹中某个图像文件的路径。它也可以是指向托管在其他位置的图像的 URL 链接。


> [!WARNING]
> **📔 注**：如果你将图像托管在其他位置，请确保该站点具有允许在其他网站上显示内容的宽松 CORS 策略。



> [!WARNING]
> **📔 注**：不要将此字段指向 `assets/Images/autogenerated-thumbnail.png` （或 `assets/images/autogenerated-thumbnail.png` 在较旧的项目中）。每当 Creator Hub 为你捕获缩略图时，都会覆盖那个确切的文件。参见 [不要将你的文件命名为 autogenerated-thumbnail.png](/docs/creator/content-creator-zh/chang-jing-bian-ji-qi/pei-zhi/scene-settings/#dont-name-your-file-autogenerated-thumbnailpng).


## 类别

你可以为场景添加类别，帮助玩家探索 Decentraland。这些类别用于 [Decentraland Places dApp](https://places.decentraland.org) 对每个地点进行分类，并让玩家更容易找到他们感兴趣的内容。

**类别** 必须从预定义选项列表中选择：

* 🎨 艺术
* 🕹️ 游戏
* 🃏 赌场
* 👥 社交
* 🎶 音乐
* 👠 时尚
* 🪙 加密
* 📚 教育
* 🛍️ 商店
* 🏢 商业
* 🏅 体育
* 🏃 跑酷

一个场景可以属于多个类别，最多可列出 3 个类别。

在 `scene.json` 中，类别列在 `tags` 数组中。

这些是预定义类别：

* `艺术`
* `游戏`
* `赌场`
* `社交`
* `音乐`
* `时尚`
* `加密`
* `教育`
* `商店`
* `商业`
* `体育`
* `跑酷`

例如，一个场景可以被标记为 `游戏` 和 `赌场` ，只需将以下内容添加到 `scene.json`

```json
  "tags": [
    "game",
    "casino",
  ],
```

之后，该场景会在 Places dApp 中列在 `游戏` 和 `赌场` 类别下。

## 年龄分级

该 **年龄分级** 字段用于对你的场景内容进行分类。Decentraland 是一个 18+ 平台。可用的选项如下：

* **🟡 `A` 适用于成人（18+）**：这是 Decentraland 在其 [使用条款](https://decentraland.org/terms)中规定的最低年龄要求。如果你的场景包含适合成人的内容，例如中度或强烈语言、暴力、露骨内容、赌博，或酒精、烟草和毒品等物质，请选择此类别。

通过 `scene.json`编辑年龄分级时，分级是一个 **单字母代码**，写作 **A** 表示成人。 `分级` 字段位于 JSON 树的根级别。

![](/docs/_remote/fcf06d87514878da9f3396fa.webp)

```json
 "rating": "A"
```

### 受限内容

场景还有第三种类别：🔴 `R` 表示受限。内容审核员会手动将此分级应用于违反 Decentraland [内容政策](https://decentraland.org/content)的场景。违规行为可能包括但不限于：

* 可疑内容或垃圾信息
* 辱骂性或仇恨性内容
* 色情或贬损内容
* 虐待儿童
* 骚扰或霸凌
* 宣扬恐怖主义/暴力
* 知识产权/版权侵权

具有此分级的场景将不会加载，任何人都无法与之交互。如果你的场景属于此类别，你应审查并更新它，以符合 [内容政策](https://decentraland.org/content).

## 功能切换

某些功能可以在特定场景中被禁用，以防玩家滥用。请在以下位置进行配置： **设置** 选项卡中的场景设置。

![](/docs/_remote/5c421faac03084ef8453fff3.webp)

目前，只有以下功能是这样处理的：

* **语音聊天**：指玩家使用麦克风与附近其他玩家通过语音聊天进行交流。
* **禁用便携式体验**：此设置将定义玩家站在你的场景内时，其任何便携式体验的行为。这不仅包括 [便携式体验](/docs/creator/content-creator-zh/chang-jing-sdk7/xiang-mu-lei-xing/portable-experiences/) 还包括 [智能穿戴设备](/docs/creator/content-creator-zh/chang-jing-sdk7/xiang-mu-lei-xing/smart-wearables/)。通过此设置，你可以选择保持它们全部启用（默认）、禁用它们，或隐藏其界面。这对于便携式体验可能让某些玩家获得不公平优势的场景很有用，例如在跑酷挑战中使用喷气背包。也建议在发生区块链交易的场景中阻止这些功能，因为恶意的便携式体验可能会冒充场景的 UI。

在 `scene.json` 文件中，这些切换项在 `featureToggles`下管理。相应功能默认启用，除非指定为 *已禁用* 在 `scene.json` 文件中。

```json
"featureToggles": {
    "voiceChat": "disabled",
    "portableExperiences": "enabled" | "disabled" | "hideUi"
},
```

如果 `featureToggles` 属性在你的 `scene.json` 文件中不存在，请在 JSON 树的根级别创建它。

### 打赏

你可以从访问你场景的玩家那里收到打赏。要启用打赏，请前往 **详情** 选项卡中的场景设置，并在 **创作者钱包地址**.

![](/docs/_remote/9c99df3549a6adf960b5d332.webp)

你也可以在 `scene.json` 文件中的 `creator` 字段下提供你场景的打赏地址。

```json
  "creator": "0x1234567890123456789012345678901234567890"
```

当玩家访问你的场景时，他们会在屏幕左上角看到一个存钱罐图标。点击它会打开一个模态窗口，玩家可以在那里给你打赏。也可以通过在地图上打开你的场景信息来访问此菜单。

![](/docs/_remote/2e01580f2f84c6ab2edcbf00.webp)

打赏模态窗口允许玩家选择要发送的 MANA 数量。玩家必须在自己的钱包中持有 MANA 才能打赏。如果你提供的地址关联了 Decentraland NAME，此模态窗口会在以太坊地址旁显示钱包所有者的姓名。

![](/docs/_remote/1cf2999882d7d551c8ac0687.webp)

每当有玩家给你打赏时，你都会在 Decentraland 通知选项卡中收到通知。

## 出生点位置

该 **出生点设置** 在 **设置** 选项卡定义玩家直接访问你的场景时的出生位置，无论是直接在浏览器中输入坐标，还是通过传送。

![](/docs/_remote/ce7ddfc8e55124a7c4396831.webp)

你的场景可能包含会阻挡玩家移动的物体，例如树或楼梯，如果玩家出生在其上方就会被卡住。你的场景也可能有高地。为防止玩家出生在无法移动的位置，你可以在特定位置设置多个出生点。

该位置由场景内的坐标组成。这些数字指的是地块内的位置，类似于你在场景代码的 Transform 组件中用来 [放置实体](/docs/creator/content-creator-zh/chang-jing-sdk7/3d-nei-rong-ji-chu/entity-positioning/).


> [!WARNING]
> **📔 注**：所有出生点都必须位于构成场景的地块内。你不能让玩家出生在这些地块空间之外。


勾选 **随机偏移** 复选框，可让出生玩家围绕出生点随机偏移。这可以防止所有玩家出生时彼此重叠，在拥挤场景中尤其不好看。 **最大偏移** 值是在 X 和 Z 轴上相对于原始出生点的最大可能距离。

设置 **相机目标** 以控制玩家进入你的场景时面向的方向。这能让你更好地控制他们的第一印象，并有助于将他们引导到特定方向。默认情况下，它指向 `{x: 8, y:1, z:8}`，这对于单地块场景来说是场景中心；对于更大的场景，则是左下角地块的中心。

点击 **添加出生点** ，以列出任意数量的出生点。玩家将随机出现在其中一个出生点。

### JSON 中的出生点

出生点也可以通过 `scene.json` 文件中的 `spawnPoints` 字段下提供你场景的打赏地址。

```json
  "spawnPoints": [
    {
      "name": "spawn1",
      "position": {
        "x": 5,
        "y": 1,
        "z": 4
      }
    }
  ],
```

单个场景可以有多个出生点。这在大型场景中尤其有用。要添加多个出生点，只需将它们列为数组。

```json
  "spawnPoints": [
    {
      "name": "spawn1",
      "position": {
        "x": 5,
        "y": 1,
        "z": 4
      }
	},
	{
      "name": "spawn2",
      "position": {
        "x": 3,
        "y": 1,
        "z": 1
      }
    }
  ],
```

当有多个出生点时，会选择离玩家所指示坐标最近的那个。

如果某个出生点被标记为 `默认`，则始终会使用它，不管它是否最近。如果有多个出生点被标记为 `默认`，则会选择最近的那个。

```json
  "spawnPoints": [
    {
      "name": "spawn1",
      "default": true,
      "position": {
        "x": 5,
        "y": 1,
        "z": 4
      }
	},
	{
      "name": "not-used",
      "position": {
        "x": 3,
        "y": 1,
        "z": 1
      }
    }
  ],
```

**出生区域**

你可以将场景中的整个区域设为出生点。通过为位置的每个维度指定一个包含两个数字的数组，玩家将会在该范围内的随机位置出现。这有助于防止进入的玩家重叠。请注意，三个维度必须使用相同的格式：要么全是单个数字，要么全是包含两个数字的数组。要将某个维度固定，使用一个包含相同数字两次的数组，例如 `"y": [1,1]`.

```json
  "spawnPoints": [
    {
      "name": "region",
      "position": {
        "x": [1,5],
        "y": [1,1],
        "z": [2,4]
      }
    }
  ],
```

在上面的示例中，玩家可能会出现在一个正方形的任意位置，其四个角位于 *1,1,2* 和 *5,1,4*.

一个场景也可以有多个出生区域，就像可以有多个出生点一样。

```json
  "spawnPoints": [
    {
      "name": "region1",
      "position": {
        "x": [1,5],
        "y": [1,1],
        "z": [2,4]
      }
    },
      {
      "name": "region2",
      "position": {
        "x": [1,5],
        "y": [1,1],
        "z": [6,8]
      }
    }
  ],
```

**旋转**

你还可以指定玩家出生时的旋转方向，让他们面向特定方向。

只需添加一个 `cameraTarget` 字段到出生点数据中。该值 `cameraTarget` 应该引用空间中的一个位置，并带有 *x*, *y* 和 *z* 相对于场景的坐标，就像 `position` 字段下提供你场景的打赏地址。

```json
  "spawnPoints": [
    {
      "name": "spawn1",
      "position": {
        "x": 5,
        "y": 1,
        "z": 4
      },
      "cameraTarget": {
        "x": 10,
        "y": 1,
        "z": 4
      }
    }
  ],
```

此示例会让玩家出生在 *5, 1, 4* 朝东，面向 *10, 1, 4*。如果出生位置是一个范围，玩家的旋转将始终与所指示的目标一致。如果有多个出生点，每个出生点都可以有各自独立的目标。

## 所需权限

该 `requiredPermissions` 属性列出了某个受限功能， [智能可穿戴设备](/docs/creator/content-creator-zh/chang-jing-sdk7/xiang-mu-lei-xing/smart-wearables/) 所使用的功能。它仅适用于智能可穿戴设备。


> [!WARNING]
> **📔 注**：普通场景（在地块中或在 Worlds 中）以及 [便携式体验](/docs/creator/content-creator-zh/chang-jing-sdk7/xiang-mu-lei-xing/portable-experiences/) 以授予所有权限的情况下运行。它们不需要此属性，添加它也不会对它们产生任何影响。


只有当智能可穿戴设备在其 `scene.json`中声明这些权限时，才可以使用这些功能。如果未声明该权限，调用将失败，Explorer 会记录一条 *权限被拒绝* 错误：

* `USE_FETCH`：使用 `fetch` 或 `signedFetch`
* `USE_WEBSOCKET`：打开到第三方服务器的 WebSocket 连接
* `USE_WEB3_API`：与玩家的钱包交互，以进行交易或签署消息
* `OPEN_EXTERNAL_LINK`：提示玩家打开指向外部网站的链接

```json
"requiredPermissions": [
    "USE_FETCH",
    "OPEN_EXTERNAL_LINK"
  ],
```

如果 `requiredPermissions` 属性在你的 `scene.json` 文件中不存在，请在 JSON 树的根级别创建它。

当智能可穿戴设备声明了这些权限中的任何一项时，Explorer 会在玩家装备它时请求玩家授权该可穿戴设备。如果玩家拒绝，该可穿戴设备的代码将不会运行。只声明你实际使用的权限，这样就不会要求玩家授予超出需要的权限。


> [!WARNING]
> **📔 注**：此页面的旧版本还列出了 `ALLOW_TO_MOVE_PLAYER_INSIDE_SCENE`, `ALLOW_TO_TRIGGER_AVATAR_EMOTE` 和 `ALLOW_MEDIA_HOSTNAMES`。当前的 Explorer 会忽略这些，因此你可以移除它们。移动玩家、播放表情动作、施加物理力以及流媒体不需要权限。


## 场景地块

当 [部署](/docs/creator/content-creator-zh/chang-jing-sdk7/fa-bu/publishing/) 一个场景时，内容会上传到场景配置中指定的坐标。一个场景可以包含单个地块，也可以包含多达数十个地块的列表。

在 Scene Editor 中的场景菜单第二个选项卡里编辑此项。

![](/docs/_remote/5bcc0f6dfa70093b896862ae.webp)

使用下拉菜单并点击 **应用布局** 以更改场景的尺寸。你也可以点击每个单独的地块，将其从布局中移除。

![](/docs/_remote/c2905f95052e96703e78829e.webp)

默认场景的坐标设置为 *0,0*。在离线开发场景时，你不需要更改这一点，除非你需要占用多个地块。在部署到你拥有部署权限的坐标之前，你需要先更改它。

你也可以在 `scene.json` 文件：

```json
 "scene": {
    "parcels": [
      "54,-14"
    ],
    "base": "54,-14"
  }
```

该 `基准` 字段定义将哪个地块视为基准地块。如果你的场景只有一个地块，基准应为该地块。如果你的场景有多个地块，基准应为左下角（西南）的地块。所有实体位置都相对于该地块的西南角来测量。

要在场景预览中显示多个地块，请列出你打算使用的所有地块。它们不必是你最终部署到的精确地块，但应当彼此相邻并保持相同的相对位置排列。

```json
 "scene": {
    "parcels": [
      "54,-14",  "55,-14"
    ],
    "base": "54,-14"
  }
```


> [!WARNING]
> **📔 注**：你能设置的最大场景尺寸为 300 x 300 个地块（总计 90,000 个地块）。


### 通过命令行设置地块

你可以通过运行以下命令来设置场景中的地块： `npx update-parcels` 命令，位于你的场景文件夹中。这对大型场景尤其有用，因为你不需要列出涉及的每一个地块。


> [!WARNING]
> **📔 注**: `update-parcels` 是一个第三方社区工具，不属于官方 Decentraland SDK，也不由 Decentraland Foundation 维护。


**单个地块**

传入一个带有场景坐标的单个参数。该坐标也会被设为基准地块。

`npx update-parcels <parcel>`

例如：

`npx update-parcels 15,-26`

**多个地块**

传入两个参数：西南和东北地块。西南地块也会被设为基础地块。

`npx update-parcels <parcel> <parcel>`


> [!NOTE]
> **💡 提示**：西南地块始终是两个 *X* 和 *Y* 坐标中数值最小的那个。


例如：

`npx update-parcels 15,-26 17,-24`

此命令会生成一个 3x3 场景，其基础地块位于 `15,-26`.

**自定义基础地块**

传入三个参数：西南和东北地块，以及要用作基础地块的地块。

`npx update-parcels <parcel> <parcel> <parcel>`


> [!WARNING]
> **📔 注**：基础地块必须是场景中的一个地块。


**非方形场景**

以上命令都会生成矩形场景。Decentraland 场景可以是 L 形或其他布局。你可以先用 `npx update-parcels` 生成一个更大的正方形，然后再手动从 `scene.json` 文件中。


> [!WARNING]
> **📔 注**：基础地块必须是场景中的一个地块。


## 天空盒时间

你可以为场景设置一个固定的时间。所有玩家看到的场景都会使用这个时间，天空盒也不会跟随昼夜循环变化。

打开场景设置，并点击 **设置** 选项卡，找到 **天空盒** 部分。取消勾选 **自动** 选项，并设置你想要的时间。

你也可以在场景代码中设置天空盒时间。为此，请在你的 `scene.json` 文件根级别添加以下部分：

```json
 "skyboxConfig": {
    "fixedTime": 36000
  }
```

这个数字表示从一天开始经过的秒数，范围从 0（表示 *00:00*）到 86400（表示 *24:00*）。任何大于 86400 的数字也会被解释为午夜。

下面还有一些有效值的示例：

* 0 秒 => *00:00*
* 21600 秒 => *06:00*
* 43200 秒 => *12:00*
* 64800 秒 => *18:00*
* 86400 秒 => *24:00*

## 地形景观

发布到 [Decentraland World](/docs/creator/content-creator-zh/chang-jing-sdk7/fa-bu/publishing-options/#decentraland-worlds) 的场景会被自动生成的草地、树木和海洋景观包围。如果这种景观与场景的美学风格不符，例如场景漂浮在开阔水面上或太空中，你可以禁用它。为此，请在你的 `scene.json` 文件根级别添加以下部分：

```json
{
	"landscapeTerrain": false
}
```

当 `landscapeTerrain` 设置为 `false`时，场景地块之外不会渲染任何内容，玩家只能看到场景周围的天空盒。移除周围地形还会释放渲染资源，这有助于让场景运行得更流畅。

如果未设置该字段，则默认值为 `true` ，景观会照常显示。


> [!WARNING]
> **📔 注**：此字段仅适用于只包含单个场景的 Worlds。在 Genesis City 中它会被忽略，因为周围环境始终由相邻地块决定。你也可以在场景的本地预览中使用它，以检查场景在没有景观时的外观。


## World 配置

在发布到 [Decentraland World](/docs/creator/content-creator-zh/chang-jing-sdk7/fa-bu/publishing-options/#decentraland-worlds)时，你可以在你的 `scene.json` 文件中使用 `worldConfiguration` 对象配置多个仅适用于 World 的设置。

### World 基本配置

要发布到 World，你必须在你的 `scene.json`:

```json
{
	"worldConfiguration": {
		"name": "my-name.dcl.eth"
	}
}
```

该 **name** 中指定 Decentraland NAME 或 ENS 域名，并且该域名必须归签署部署的钱包所有（或归通过访问控制列表授予权限的任意钱包所有）。

### 通信服务配置

该 `fixedAdapter` 属性表示场景应使用哪个通信服务。目前只有 `offline:offline` 值可用。设置后，场景将完全不使用任何通信服务，加入该 world 的每个用户都将始终独自一人。如果不设置，World 内容服务器会根据其配置方式生成一个合适的值。

```json
{
	"worldConfiguration": {
		"name": "my-name.dcl.eth",
		"fixedAdapter": "offline:offline"
	}
}
```


> [!WARNING]
> **📔 注**：将 `fixedAdapter` 设置为 `"offline:offline"` （或在 Creator Hub 的 World Settings 中启用 **单人模式** ）会禁用直播。流媒体功能依赖通信层向观看者传递视频。如果你需要在 world 中进行直播，请不要使用此选项。


### Places 列表配置

所有 Worlds 默认都会自动列在 Places 页面上，除非你选择退出。如果你希望不让自己的 Worlds 被 Places 索引，可以添加以下内容：

```json
{
	"worldConfiguration": {
		"name": "my-name.dcl.eth",
		"placesConfig": {
			"optOut": true
		}
	}
}
```

### 完整示例

下面是一个包含所有 World 配置选项的完整示例：

```json
{
	"worldConfiguration": {
		"name": "my-name.dcl.eth",
		"fixedAdapter": "offline:offline",
		"placesConfig": {
			"optOut": true
		}
	}
}
```

参见 [发布到 Worlds](/docs/creator/content-creator-zh/chang-jing-sdk7/fa-bu/publishing/#publishing-to-worlds) 了解更多关于部署到 Worlds 的信息。

## 从场景代码中获取元数据

[场景 API 参考](https://js-sdk-toolchain.pages.dev/modules/js_runtime_apis.__system_Scene_)

你可能需要场景的代码来访问场景元数据中的字段，例如场景部署到的地块或出生点位置。这对于需要复制的场景，或希望在其他场景中复用的代码尤其有用。对于需要知道场景边界在哪里的库来说，这也非常有用。

要访问这些数据，首先导入 `getSceneInformation` 函数：

```ts
import { getSceneInformation } from '~system/Runtime'
```

然后你就可以调用 `getSceneInformation()` 函数，它会返回一个 JSON 对象，其中包含 scene.json 文件的大部分内容。下面的示例展示了如何从该函数的返回值中访问几个更常见的字段：

```ts
import { getSceneInformation } from '~system/Runtime'

executeTask(async () => {
  const sceneInfo = await getSceneInformation({})

  if (!sceneInfo) return
  console.log("SCENE INFO: ", sceneInfo)
})
```


> [!WARNING]
> **📔 注**: `getSceneInformation()` 需要以 [异步函数](/docs/creator/content-creator-zh/chang-jing-sdk7/bian-cheng-mo-shi/async-functions/)的形式运行，因为返回数据时响应可能会延迟几分之一秒或更久。请勿使用已弃用的 `getSceneInfo()` 函数。


由 `getSceneInformation()` 返回的对象包含以下内容：

* `baseUrl`：场景内容托管的基础 URL
* `content`：包含场景所有文件及其哈希值的数组，可与 baseUrl 一起用于检索这些文件。
* `metadataJson`：场景 scene.json 的完整内容，字符串形式。你必须先解析它才能获取特定值。
* `urn`：整个场景的唯一 urn。

下面的示例会解析 `metadataJson` 中的内容，以获取 scene.json 文件中各属性的值

```ts
import { getSceneInformation } from '~system/Runtime'

executeTask(async () => {
	const sceneInfo = await getSceneInformation({})

	if (!sceneInfo) return

	const sceneJson = JSON.parse(sceneInfo.metadataJson)
	const spawnPoints = sceneJson.spawnPoints
	const parcels = sceneJson.scene.parcels
	console.log({ parcels, spawnPoints })
})
```
