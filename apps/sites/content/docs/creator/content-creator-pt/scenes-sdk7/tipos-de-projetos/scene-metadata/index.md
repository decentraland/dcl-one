# Metadados da cena

Uma scene é um projeto da Decentraland que é delimitado espacialmente e mapeado para um ou vários parcels. Se uma scene for implantada no mapa da Decentraland Genesis City, os jogadores podem experimentá-la visitando as coordenadas da scene. Se uma scene for implantada em um [World](/docs/creator/content-creator-pt/scenes-sdk7/publicacao/publishing-options/#decentraland-worlds), os jogadores podem visitá-la por URL.

Ver [Arquivos em uma scene](/docs/creator/content-creator-pt/scenes-sdk7/tipos-de-projetos/scene-files/) para ver uma lista dos arquivos usados em um projeto de scene.

## Metadados

Para editar os metadados de uma scene no [Scene Editor no Creator Hub](/docs/creator/content-creator-pt/scene-editor/primeiros-passos/about-editor/), abra uma scene e clique no **ícone de lápis**.

![](/docs/_remote/a64bc0ae30e4d852f97ccd78.webp)

Isso abre o menu da scene, onde você pode configurar várias propriedades.

![](/docs/_remote/c3618719dd688d071c5d267b.webp)

Como alternativa, você pode editar diretamente o `scene.json` arquivo, onde todos esses valores são armazenados.


> [!WARNING]
> **📔 Observação**: Não adicione campos personalizados ao `scene.json` arquivo que não sejam mencionados nesta página, pois isso pode causar problemas ao carregar sua scene.


## Título, descrição e imagem da scene

É muito importante dar à sua scene um título, uma descrição e uma imagem em miniatura para atrair jogadores e ajudá-los a saber o que esperar.

Os jogadores verão isso exibido em um modal quando selecionarem os parcels da sua scene no mapa. Eles também verão isso em uma tela de confirmação ao serem [teletransportados](/docs/creator/content-creator-pt/scenes-sdk7/interatividade/external-links/) para lá por outra scene. Configurar dados atraentes aqui pode ajudar significativamente a gerar tráfego para sua scene.

Quando os jogadores navegam pelo mundo e entram na sua scene, eles podem ler o título da scene abaixo do minimapa.

![](/docs/_remote/0e2898c7018cc52a2d72b72d.webp)

Adicione esses dados pelo menu da scene no Scene Editor.

Caso queira que outros desenvolvedores possam entrar em contato com você, você também pode adicionar informações de contato à sua scene.


> [!NOTE]
> **📔 Observação**: Os Worlds mantêm seu próprio nome, descrição e miniatura, separados dos metadados da scene. Se um World contém uma única scene, os metadados do World são atualizados a partir dos metadados da scene a cada publicação. Se ele contém várias scenes, os metadados do World são independentes e só podem ser editados na aba **Gerenciar** do Creator Hub. Veja [Metadados do World vs metadados da scene](/docs/creator/content-creator-pt/scene-editor/publicar/publish-scene/#world-metadata-vs-scene-metadata).

## Categorias

Você pode adicionar categorias à sua scene para ajudar os jogadores a explorar Decentraland. Elas são usadas no [Decentraland Places dApp](https://places.decentraland.org) para categorizar cada lugar e facilitar para os jogadores encontrarem o que lhes interessa.

**Categorias** precisam ser escolhidas de uma lista predefinida de opções:

* 🎨 Arte
* 🕹️ Jogo
* 🃏 Cassino
* 👥 Social
* 🎶 Música
* 👠 Moda
* 🪙 Cripto
* 📚 Educação
* 🛍️ Loja
* 🏢 Negócios
* 🏅 Esportes
* 🏃 Parkour

Uma scene pode pertencer a mais de uma categoria, com no máximo 3 categorias listadas.

No `scene.json` as categorias são listadas no `tags` array.

Estas são as categorias predefinidas:

* `art`
* `game`
* `casino`
* `social`
* `music`
* `fashion`
* `crypto`
* `education`
* `shop`
* `business`
* `sports`
* `parkour`

Por exemplo, uma scene pode ser marcada como `game` e `casino` adicionando o seguinte ao `scene.json`

```json
  "tags": [
    "game",
    "casino",
  ],
```

Depois disso, a scene é listada no Places dApp sob as `game` e `casino` categorias.

## Classificação etária

O **Classificação etária** campo é usado para classificar o conteúdo da sua scene. Decentraland é uma plataforma para maiores de 18 anos. A seguinte opção está disponível:

* **🟡 `A` para Adultos (18+)**: Esta é a idade mínima exigida, conforme especificado nos [Termos de Uso](https://decentraland.org/terms). Escolha esta categoria se sua scene apresentar conteúdo apropriado para adultos, como linguagem moderada ou intensa, violência, conteúdo explícito, apostas ou substâncias como álcool, tabaco e drogas.

Ao editar a Age Rating por meio do `scene.json`, a classificação é um **código de uma única letra**, escreva **A** para adultos. O `rating` fica no nível raiz da árvore JSON.

![](/docs/_remote/fcf06d87514878da9f3396fa.webp)

```json
 "rating": "A"
```

### Conteúdo restrito

Há uma terceira categoria para scenes: 🔴 `R` para Restricted. Esta classificação é aplicada manualmente pelos Moderadores de Conteúdo a scenes que violam a [Política de Conteúdo](https://decentraland.org/content). As violações podem incluir, mas não se limitam a:

* Conteúdo suspeito ou spam
* Conteúdo abusivo ou odioso
* Conteúdo sexual ou degradante
* Abuso infantil
* Assédio ou intimidação
* Promoção de terrorismo/violência
* Violação de PI/direitos autorais

Scenes com essa classificação não serão carregadas e ninguém poderá interagir com elas. Se a sua scene se enquadrar nesta categoria, você deve revisá-la e atualizá-la para cumprir a [Política de Conteúdo](https://decentraland.org/content).

## Alternadores de recursos

Há certos recursos que podem ser desativados em scenes específicas para que os jogadores não possam usá-los de forma abusiva. Configure isso na aba **Configurações** das configurações da scene.

![](/docs/_remote/5c421faac03084ef8453fff3.webp)

Atualmente, apenas o seguinte recurso é tratado assim:

* **Voice Chat**: Refere-se a jogadores usando seus microfones para conversar por Voice Chat com outros jogadores próximos.
* **Desativar Portable Experiences**: Esta configuração definirá o comportamento de qualquer portable experience de um jogador enquanto ele estiver dentro da sua scene. Isso inclui não apenas [portable experiences](/docs/creator/content-creator-pt/scenes-sdk7/tipos-de-projetos/portable-experiences/) mas também [smart wearables](/docs/creator/content-creator-pt/scenes-sdk7/tipos-de-projetos/smart-wearables/). Com essa configuração, você pode escolher manter todos habilitados (padrão), desativá-los ou ocultar a UI deles. Isso é útil para scenes em que portable experiences podem dar vantagem injusta a alguns jogadores, por exemplo usando um jetpack em um desafio de parkour. Também é recomendado impedir isso em scenes onde ocorrem transações blockchain e onde uma portable experience maliciosa poderia potencialmente se passar pela UI da scene.

No `scene.json` arquivo, esses alternadores são gerenciados em `featureToggles`. Os recursos correspondentes ficam habilitados por padrão, a menos que sejam especificados como *desativados* no `scene.json` arquivo.

```json
"featureToggles": {
    "voiceChat": "disabled",
    "portableExperiences": "enabled" | "disabled" | "hideUi"
},
```

Se uma `featureToggles` propriedade não existir no seu `scene.json` arquivo, crie-a no nível raiz da árvore JSON.

### Gorjetas

Você pode receber gorjetas de jogadores que visitam sua scene. Para habilitar gorjetas, vá para a aba **Detalhes** nas configurações da scene e informe um endereço Ethereum em **Endereço da carteira do criador**.

![](/docs/_remote/9c99df3549a6adf960b5d332.webp)

Você também pode informar o endereço para gorjetas da sua scene no arquivo `scene.json` , no campo `creator` .

```json
  "creator": "0x1234567890123456789012345678901234567890"
```

Quando um jogador visita sua scene, ele verá um ícone de cofrinho no canto superior esquerdo da tela. Clicar nele abre um modal onde ele pode enviar uma gorjeta. Esse menu também pode ser acessado abrindo as informações da sua scene no mapa.

![](/docs/_remote/2e01580f2f84c6ab2edcbf00.webp)

O modal de gorjeta permite que o jogador selecione a quantidade de MANA que deseja enviar. O jogador precisa ter MANA na sua carteira para enviar uma gorjeta. Se o endereço que você forneceu estiver vinculado a um NAME da Decentraland, esse modal mostrará o nome do titular da carteira além do endereço Ethereum.

![](/docs/_remote/1cf2999882d7d551c8ac0687.webp)

Você receberá uma notificação na aba de notificações da Decentraland sempre que um jogador lhe enviar uma gorjeta.

## Local de spawn

O **Configurações de spawn** no **Configurações** definem onde os jogadores fazem spawn quando acessam sua scene diretamente, seja digitando as coordenadas diretamente no navegador ou por teletransporte.

![](/docs/_remote/ce7ddfc8e55124a7c4396831.webp)

Sua scene pode ter objetos que bloqueiam a movimentação dos jogadores se eles fizerem spawn em cima deles, como árvores ou escadas. Sua scene também pode ter terreno elevado. Para evitar que os jogadores façam spawn em locais onde não possam se mover, você pode definir várias posições de spawn em locais específicos.

A posição consiste em coordenadas dentro da scene. Esses números se referem a uma posição dentro do parcel, semelhante ao que você usaria no código da scene em um componente Transform para [posicionar uma entity](/docs/creator/content-creator-pt/scenes-sdk7/fundamentos-de-conteudo-3d/entity-positioning/).


> [!WARNING]
> **📔 Observação**: Todos os spawn points devem estar dentro dos parcels que compõem a scene. Você não pode fazer spawn de um jogador fora do espaço desses parcels.


Marque a caixa **Deslocamento aleatório** para deslocar aleatoriamente os jogadores em torno do spawn point. Isso evita que todos os jogadores apareçam sobrepostos quando fazem spawn, o que fica especialmente ruim em scenes lotadas. O valor de **Deslocamento máximo** é a distância máxima possível a partir do spawn point original, tanto nos eixos X quanto Z.

Defina o **Destino da câmera** para controlar a direção para a qual os jogadores olham quando entram na sua scene. Isso lhe dá melhor controle sobre a primeira impressão deles e pode ajudar a orientá-los em uma direção específica. Por padrão, isso aponta para `{x: 8, y:1, z:8}`, que é o centro da scene para scenes de um único parcel, ou o centro do parcel inferior esquerdo para scenes maiores.

Clique **Adicionar ponto de spawn** para listar quantos spawn points você quiser. Os jogadores aparecerão aleatoriamente em um deles.

### Spawn points no JSON

Os spawn points também podem ser configurados via o arquivo `scene.json` , na `spawnPoints` .

```json
  "spawnPoints": [
    {
      "name": "spawn1",
      "position": {
        "x": 5,
        "y": 1,
        "z": 4
      }
    }
  ],
```

Uma única scene pode ter vários spawn points. Isso é especialmente útil em scenes grandes. Para ter muitos spawn points, basta listá-los como um array.

```json
  "spawnPoints": [
    {
      "name": "spawn1",
      "position": {
        "x": 5,
        "y": 1,
        "z": 4
      }
	},
	{
      "name": "spawn2",
      "position": {
        "x": 3,
        "y": 1,
        "z": 1
      }
    }
  ],
```

Quando há vários spawn points, é selecionado o mais próximo das coordenadas indicadas pelo jogador.

Se um spawn point estiver marcado como `padrão`, ele sempre será usado, independentemente de ser o mais próximo. Se vários spawn points estiverem marcados como `padrão`, o mais próximo será selecionado.

```json
  "spawnPoints": [
    {
      "name": "spawn1",
      "default": true,
      "position": {
        "x": 5,
        "y": 1,
        "z": 4
      }
	},
	{
      "name": "not-used",
      "position": {
        "x": 3,
        "y": 1,
        "z": 1
      }
    }
  ],
```

**Regiões de spawn**

Você pode definir uma região inteira na scene para atuar como um spawn point. Ao especificar um array de dois números para cada dimensão da posição, os jogadores aparecerão em um local aleatório dentro desse intervalo. Isso ajuda a evitar que jogadores que entram se sobreponham. Observe que as três dimensões devem usar o mesmo formato: ou todos números únicos, ou todos arrays de dois números. Para manter uma dimensão fixa, use um array com o mesmo número duas vezes, como `"y": [1,1]`.

```json
  "spawnPoints": [
    {
      "name": "region",
      "position": {
        "x": [1,5],
        "y": [1,1],
        "z": [2,4]
      }
    }
  ],
```

No exemplo acima, os jogadores podem aparecer em qualquer ponto do quadrado cujos cantos estão em *1,1,2* e *5,1,4*.

Uma scene também pode ter várias spawn regions, assim como pode ter vários spawn points.

```json
  "spawnPoints": [
    {
      "name": "region1",
      "position": {
        "x": [1,5],
        "y": [1,1],
        "z": [2,4]
      }
    },
      {
      "name": "region2",
      "position": {
        "x": [1,5],
        "y": [1,1],
        "z": [6,8]
      }
    }
  ],
```

**Rotação**

Você também pode especificar a rotação dos jogadores quando eles fazem spawn, para que fiquem olhando em uma direção específica.

Basta adicionar um campo `cameraTarget` aos dados do spawn point. O valor de `cameraTarget` deve fazer referência a um local no espaço, com coordenadas *x*, *y* e *z* relativas à scene, assim como a `position` .

```json
  "spawnPoints": [
    {
      "name": "spawn1",
      "position": {
        "x": 5,
        "y": 1,
        "z": 4
      },
      "cameraTarget": {
        "x": 10,
        "y": 1,
        "z": 4
      }
    }
  ],
```

Este exemplo faz spawn de um jogador em *5, 1, 4* virado para o leste em direção a *10, 1, 4*. Se a posição de spawn for um intervalo, a rotação do jogador sempre corresponderá ao alvo indicado. Se houver vários spawn points, cada um pode ter seu próprio alvo separado.

## Permissões necessárias

O `requiredPermissions` propriedade lista quais recursos restritos um [smart wearable](/docs/creator/content-creator-pt/scenes-sdk7/tipos-de-projetos/smart-wearables/) usa. Isso se aplica apenas a smart wearables.


> [!WARNING]
> **📔 Observação**: Scenes regulares (em parcels ou em Worlds) e [portable experiences](/docs/creator/content-creator-pt/scenes-sdk7/tipos-de-projetos/portable-experiences/) funcionam com cada permissão concedida. Elas não precisam dessa propriedade, e adicioná-la não tem efeito sobre elas.


Um smart wearable só pode usar esses recursos se os declarar em seu `scene.json`. Se a permissão não for declarada, a chamada falha e o Explorer registra um erro de *permissão negada* erro:

* `USE_FETCH`: Envie solicitações HTTP para servidores de terceiros com `fetch` ou `signedFetch`
* `USE_WEBSOCKET`: Abra conexões websocket com servidores de terceiros
* `USE_WEB3_API`: Interaja com a carteira do jogador para fazer transações ou assinar mensagens
* `OPEN_EXTERNAL_LINK`: Solicite que o jogador abra um link para um site externo

```json
"requiredPermissions": [
    "USE_FETCH",
    "OPEN_EXTERNAL_LINK"
  ],
```

Se uma `requiredPermissions` propriedade não existir no seu `scene.json` arquivo, crie-a no nível raiz da árvore JSON.

Quando um smart wearable declara qualquer uma dessas permissões, o Explorer pede ao jogador que autorize o wearable quando ele o equipar. Se o jogador recusar, o código do wearable não será executado. Declare apenas as permissões que você realmente usa, para que os jogadores não sejam solicitados a conceder mais do que o necessário.


> [!WARNING]
> **📔 Observação**: Versões mais antigas desta página também listavam `ALLOW_TO_MOVE_PLAYER_INSIDE_SCENE`, `ALLOW_TO_TRIGGER_AVATAR_EMOTE` e `ALLOW_MEDIA_HOSTNAMES`. O Explorer atual ignora isso, então você pode removê-los. Mover o jogador, reproduzir emotes, aplicar forças físicas e fazer streaming de mídia não precisam de permissão.


## Parcels da scene

Ao [implantar](/docs/creator/content-creator-pt/scenes-sdk7/publicacao/publishing/) uma scene, o conteúdo é enviado para as coordenadas atribuídas na configuração da scene. Uma scene pode incluir um único parcel ou uma lista de até dezenas deles.

Edite isso na segunda aba do menu da scene no Scene Editor.

![](/docs/_remote/5bcc0f6dfa70093b896862ae.webp)

Use os menus suspensos e clique em **Aplicar layout** para alterar as dimensões da sua scene. Você também pode clicar em cada parcel individual para desativá-lo do seu layout.

![](/docs/_remote/c2905f95052e96703e78829e.webp)

A scene padrão tem suas coordenadas definidas como *0,0*. Você não precisa alterar isso ao desenvolver uma scene offline, a menos que precise ocupar vários parcels. Você precisará alterar isso antes de implantar nas coordenadas para as quais você tem permissão de implantação.

Você também pode alterar as coordenadas da scene no arquivo `scene.json` arquivo:

```json
 "scene": {
    "parcels": [
      "54,-14"
    ],
    "base": "54,-14"
  }
```

O `base` campo define qual parcel considerar o parcel base. Se a sua scene tiver um único parcel, o base deve ser esse parcel. Se a sua scene tiver vários parcels, o base deve ser o parcel inferior esquerdo (sudoeste). Todas as posições das entities são medidas em relação ao canto sudoeste desse parcel.

Para exibir vários parcels na pré-visualização da scene, liste quantos parcels você pretende usar. Eles não precisam ser exatamente os parcels para os quais você vai implantar, mas todos devem ser adjacentes e organizados nas mesmas posições relativas.

```json
 "scene": {
    "parcels": [
      "54,-14",  "55,-14"
    ],
    "base": "54,-14"
  }
```


> [!WARNING]
> **📔 Observação**: O maior tamanho de scene que você pode definir é 300 x 300 parcels (90.000 parcels no total).


### Defina os parcels pela linha de comando

Você pode definir os parcels da sua scene executando o comando `npx update-parcels` na pasta da sua scene. Isso é especialmente útil para scenes grandes, pois você não precisa listar cada parcel envolvido.


> [!WARNING]
> **📔 Observação**: `update-parcels` é uma ferramenta da comunidade de terceiros; ela não faz parte do SDK oficial da Decentraland e não é mantida pela Decentraland Foundation.


**Parcel único**

Passe um único argumento com as coords da scene. Essa coordenada também é definida como o parcel base.

`npx update-parcels <parcel>`

Por exemplo:

`npx update-parcels 15,-26`

**Vários parcels**

Passe dois argumentos: os parcels do sudoeste e do nordeste. O parcel do sudoeste também é definido como o parcel base.

`npx update-parcels <parcel> <parcel>`


> [!NOTE]
> **💡 Dica**: O parcel do sudoeste é sempre aquele com os menores números em ambas as *X* e *Y* coordenadas.


Por exemplo:

`npx update-parcels 15,-26 17,-24`

Este comando gera uma scene 3x3, com seu parcel base em `15,-26`.

**Personalizar Parcel Base**

Passe três argumentos: os parcels do sudoeste e do nordeste, e o parcel a ser usado como parcel base.

`npx update-parcels <parcel> <parcel> <parcel>`


> [!WARNING]
> **📔 Observação**: O parcel base deve ser um dos parcels da scene.


**Scenes não quadradas**

Os comandos acima geram todos scenes de formato retangular. As scenes de Decentraland podem ter formato em L ou outras configurações. Você pode gerar um quadrado maior com `npx update-parcels` e depois remover manualmente os parcels excedentes da `scene.json` arquivo.


> [!WARNING]
> **📔 Observação**: O parcel base deve ser um dos parcels da scene.


## Hora do dia da Skybox

Você pode definir uma hora do dia fixa para a sua scene. Todos os jogadores verão a scene com essa hora do dia, e a skybox não seguirá o ciclo dia/noite.

Abra as configurações da scene e clique na **Configurações** aba para encontrar a **Skybox** seção. Desmarque a **Auto** opção e defina a hora do dia desejada.

Você também pode definir a hora do dia da skybox no código da sua scene. Para isso, adicione a seguinte seção ao seu `scene.json` na raiz:

```json
 "skyboxConfig": {
    "fixedTime": 36000
  }
```

O número se refere à quantidade de segundos desde o início do dia, variando de 0 (representando *00:00*) até 86400 (representando *24:00*). Qualquer número maior que 86400 também é interpretado como meia-noite.

Aqui estão mais alguns exemplos de valores válidos:

* 0 segundos => *00:00*
* 21600 segundos => *06:00*
* 43200 segundos => *12:00*
* 64800 segundos => *18:00*
* 86400 segundos => *24:00*

## Terreno da paisagem

Scenes publicadas em um [World de Decentraland](/docs/creator/content-creator-pt/scenes-sdk7/publicacao/publishing-options/#decentraland-worlds) são cercadas por uma paisagem gerada automaticamente de gramado, árvores e mar. Se essa paisagem não corresponder à estética da sua scene, por exemplo, uma scene que flutua em águas abertas ou no espaço, você pode desativá-la. Para isso, adicione o seguinte campo ao seu `scene.json` na raiz:

```json
{
	"landscapeTerrain": false
}
```

Com `landscapeTerrain` definido como `false`, nada é renderizado além dos parcels da sua scene, e os jogadores veem apenas a skybox ao redor da scene. Remover o terreno ao redor também libera recursos de renderização, o que pode ajudar sua scene a rodar de forma mais fluida.

Se o campo não for definido, o padrão é `true` e a paisagem é exibida normalmente.


> [!WARNING]
> **📔 Observação**: Este campo se aplica apenas a Worlds que contenham uma única scene. Ele é ignorado em Genesis City, onde os arredores são sempre determinados pelos parcels vizinhos. Você também pode usá-lo ao executar uma prévia local da sua scene, para verificar como a scene fica sem a paisagem.


## Configuração do World

Ao publicar em um [World de Decentraland](/docs/creator/content-creator-pt/scenes-sdk7/publicacao/publishing-options/#decentraland-worlds), você pode configurar várias definições específicas do World no seu `scene.json` arquivo usando o `worldConfiguration` objeto.

### Configuração básica do World

Para publicar em um World, você deve especificar o domínio NAME ou ENS no seu `scene.json`:

```json
{
	"worldConfiguration": {
		"name": "my-name.dcl.eth"
	}
}
```

O **name** especificado pode ser um Decentraland NAME ou um domínio ENS e deve pertencer à wallet que assina o deployment (ou a qualquer wallet que tenha recebido permissão via Access Control Lists).

### Configuração do serviço de comunicação

O `fixedAdapter` propriedade indica qual Communication Service deve ser usado pela scene. Por enquanto, apenas o `offline:offline` valor é permitido. Quando definido, a scene não terá nenhum Communication Service, e cada usuário que entrar nesse World estará sempre sozinho. Se não for definido, o content server do Worlds gerará um valor adequado com base em como ele está configurado.

```json
{
	"worldConfiguration": {
		"name": "my-name.dcl.eth",
		"fixedAdapter": "offline:offline"
	}
}
```


> [!WARNING]
> **📔 Observação**: Definir `fixedAdapter` como `"offline:offline"` (ou ativar **Single Player** em World Settings via o Creator Hub) desativa o live streaming. O recurso de streaming depende da camada de comunicação para entregar vídeo aos espectadores. Se você precisar de live streaming no seu World, não use esta opção.


### Configuração da listagem no Places

Todos os Worlds são listados automaticamente na página do Places, a menos que você opte por não participar. Se quiser impedir que seus Worlds sejam indexados no Places, você pode adicionar o seguinte:

```json
{
	"worldConfiguration": {
		"name": "my-name.dcl.eth",
		"placesConfig": {
			"optOut": true
		}
	}
}
```

### Exemplo completo

Aqui está um exemplo completo com todas as opções de configuração do World:

```json
{
	"worldConfiguration": {
		"name": "my-name.dcl.eth",
		"fixedAdapter": "offline:offline",
		"placesConfig": {
			"optOut": true
		}
	}
}
```

Ver [Publicando em Worlds](/docs/creator/content-creator-pt/scenes-sdk7/publicacao/publishing/#publishing-to-worlds) para mais informações sobre deployment em Worlds.

## Obter metadata a partir do código da scene

[Referência da Scene API](https://js-sdk-toolchain.pages.dev/modules/js_runtime_apis.__system_Scene_)

Você pode precisar do código da sua scene para acessar campos dos metadata da scene, como os parcels para os quais a scene é implantada, ou as posições dos spawn points. Isso é especialmente útil para scenes que devem ser replicadas, ou para código que deve ser reutilizado em outras scenes. Também é muito útil para libraries que precisam saber onde estão os limites da scene.

Para acessar esses dados, primeiro importe a `getSceneInformation` função:

```ts
import { getSceneInformation } from '~system/Runtime'
```

Depois, você pode chamar a `getSceneInformation()` função, que retorna um objeto JSON que inclui a maior parte do conteúdo do arquivo scene.json. O exemplo abaixo mostra como acessar vários dos campos mais comuns da resposta dessa função:

```ts
import { getSceneInformation } from '~system/Runtime'

executeTask(async () => {
  const sceneInfo = await getSceneInformation({})

  if (!sceneInfo) return
  console.log("SCENE INFO: ", sceneInfo)
})
```


> [!WARNING]
> **📔 Observação**: `getSceneInformation()` precisa ser executado como um [async function](/docs/creator/content-creator-pt/scenes-sdk7/padroes-de-programacao/async-functions/), pois a resposta pode demorar uma fração de segundo ou mais para retornar os dados. Não use a função descontinuada `getSceneInfo()` função.


O objeto retornado por `getSceneInformation()` inclui o seguinte:

* `baseUrl`: A URL base onde o conteúdo da scene está hospedado
* `content`: Um array com todos os files da scene, incluindo seu hash, que pode ser usado junto com a baseUrl para recuperá-los.
* `metadataJson`: O conteúdo completo do scene.json da scene, como uma string. Você deve fazer o parse disso para obter valores específicos.
* `urn`: A urn única para a scene como um todo.

O exemplo abaixo faz o parse do conteúdo de `metadataJson` para obter valores de propriedades no arquivo scene.json

```ts
import { getSceneInformation } from '~system/Runtime'

executeTask(async () => {
	const sceneInfo = await getSceneInformation({})

	if (!sceneInfo) return

	const sceneJson = JSON.parse(sceneInfo.metadataJson)
	const spawnPoints = sceneJson.spawnPoints
	const parcels = sceneJson.scene.parcels
	console.log({ parcels, spawnPoints })
})
```
