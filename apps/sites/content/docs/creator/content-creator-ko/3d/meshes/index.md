> Decentraland로 가져온 3D 모델에서 지원되는 메시 속성을 알아보세요.

# 메시

3D 모델에는 *메시* 삼각형으로 이루어진 *면*. 이 면들은 서로 *모서리에서* (서로 맞닿는 선) 그리고 *정점* (모서리가 만나는 점).


> [!NOTE]
> **💡 팁**: 다음을 설치하세요 [Decentraland Tools Blender 플러그인](https://extensions.blender.org/add-ons/decentraland-tools/). 여기에는 3D 모델, 웨어러블 및 이모트를 편집하고 내보내는 데 유용한 여러 기능이 포함되어 있습니다.


## 공간 제한

씬의 모든 3D 모델은 해당 파셀의 한계 안에 들어와야 합니다. 프리뷰를 실행할 때 모델의 일부가 이 한계를 벗어나면, 벗어난 부분은 잘려서 렌더링되지 않습니다.

![](/docs/_remote/9ba86deac82448c396d45bba.webp)

Creator Hub 편집기에서는 모델이 붉게 색조가 입혀지고 바운딩 박스가 빨간색으로 표시됩니다.

![](/docs/_remote/ac6b1ca6eff1a48fc7dfe75d.webp)


> [!NOTE]
> **📔 참고**: Decentraland의 이전 웹 클라이언트에서는 성능상의 이유로, 3D 모델의 일부가 범위를 벗어나기만 해도, 바운딩 박스만 벗어나 있더라도 전체 모델이 렌더링되지 않았습니다. Decentraland 2.0 데스크톱 클라이언트부터는 모델에서 범위를 벗어난 부분만 잘립니다. 씬 안에 있는 모델의 부분은 렌더링됩니다.


## 바운딩 박스

모든 정점이 씬 영역 안에 깔끔하게 들어가 있지만, 대부분이 비어 있고 씬 한계를 넘어 확장된 큰 바운딩 박스를 가진 모델이 있다면, Creator Hub에서는 전체 모델이 씬 한계 밖으로 표시됩니다. 파셀 안에 있는 모델의 부분은 올바르게 렌더링되며, 씬을 게시할 수 있습니다.

모든 메시에는 해당 형태의 한계를 둘러싸는 바운딩 박스가 있습니다. Decentraland 안에서 3D 모델을 더 잘 활용하려면, 바운딩 박스가 필요 이상으로 모델 바깥으로 확장되지 않도록 하세요.

이 문제를 피하려면 3D 모델을 정리해서 메시의 위치와 회전을 재설정하고, 바운딩 박스가 감싸는 메시보다 더 바깥으로 나가지 않게 할 수 있습니다.

![](/docs/_remote/7c3c5e5108be6fd7e142dbf6.webp)

*Blender에서는 오브젝트를 선택한 다음 Ctrl+A를 누르고 ‘모든 변환 적용’을 선택하면 됩니다.*

예를 들어, 모델의 경계 근처에 있는 하위 메시를 회전할 때는 주의하세요. 바운딩 박스는 정육면체이므로, 메시가 둥글더라도 45° 회전한 뒤에는 바운딩 박스의 모서리가 밖으로 튀어나올 수 있습니다.

![](/docs/_remote/15f51a636f43103faeefa105.webp)

모델의 모든 메시의 회전과 스케일을 베이크해서, 필요 이상으로 밖으로 뻗는 원치 않는 바운딩 박스가 없도록 하는 것을 권장합니다.

## 삼각형 제한

Decentraland는 서로 다른 수많은 씬과 오브젝트가 같은 3D 공간에서 즉석으로 다운로드되는 열린 세계이기 때문에, 플레이 중 좋은 성능을 유지하려면 메시를 최적화하는 것이 중요합니다. 그런 의미에서, 메시와 관련해 항상 염두에 두어야 할 몇 가지 씬 제한이 있습니다:

> n은 씬이 차지하는 파셀의 수를 나타냅니다.

* **삼각형:** n x 10000 씬 내 모든 모델의 총 삼각형 수.
* **높이:** 330미터, 파셀 수와 관계없이.
* **파일 크기:** 파셀당 15 MB - 최대 300 MB 콘텐츠 서버에 업로드된 파일의 총 크기입니다. 3D 모델과 오디오가 포함됩니다. node.js 패키지처럼 업로드되지 않는 파일은 포함되지 않습니다.
* **파일당 최대 파일 크기 50 MB** 씬에 있는 어떤 유형의 개별 파일도, 씬에 파셀이 몇 개 있든 상관없이 50 MB를 넘을 수 없습니다.

더 자세한 내용은 모든 씬 제한을 확인하세요 [여기에서.](/docs/creator/sdk7/optimizing/scene-limitations/)


> [!WARNING]
> **🔥최적화 팁🔥: 폴리곤 수 추가** 유용한 팁은 모델의 폴리 수를 항상 추적하는 것입니다. Blender에서 이를 하려면 뷰포트 오버레이 패널에서 통계를 켜야 합니다.

## 큰 씬의 메시

메시를 만들 때는 다음 두 가지 모범 사례를 염두에 두어야 합니다:

* **모듈성:** 큰 메시를 더 작은 모듈식 부품으로 나누세요. 예를 들어 건물 전체를 하나의 메시로 만드는 대신, 건물의 각 벽, 바닥, 구역을 별도의 메시로 나눌 수 있습니다. 이렇게 하면 Unity의 프러스텀 컬링이 더 효과적으로 작동해, 렌더링할 때 보이는 부분만 고려하면 됩니다. 또한 메모리 점유도 개선됩니다. 하나의 메시를 여러 위치에서 같은 오브젝트에 여러 번 재사용할 수 있기 때문입니다(이를 위해서는 SDK7 씬 정의에서 같은 메시를 참조하거나, Blender에서 씬을 내보낼 때 중복 오브젝트 대신 인스턴스를 사용해야 합니다).
* **바운딩 볼륨**: 각 오브젝트의 바운딩 볼륨이 가능한 한 꼭 맞게 들어가도록 하세요. 바운딩 볼륨 안의 불필요한 공간은 보이지 않는 오브젝트가 렌더링되게 만들 수 있습니다.

## 오브젝트 인스턴싱과 오브젝트 복제

Blender에서는 오브젝트를 복제하면 완전히 분리된 사본이 만들어지고, 오브젝트를 인스턴싱하면 원본 오브젝트와 같은 데이터를 공유하는 복제본이 만들어집니다.

오브젝트가 복제되면, 그 오브젝트의 모든 기하 구조, 재질, 애니메이션을 포함한 완전히 독립적인 데이터 집합을 가진 새 오브젝트가 생성됩니다. 즉, 원본 오브젝트에 가한 변경 사항은 복제된 오브젝트에 반영되지 않으며, 그 반대도 마찬가지입니다.

반면 오브젝트가 인스턴싱되면, 원본 오브젝트에 가한 변경 사항이 모든 인스턴스에 반영되며 그 반대도 마찬가지입니다. 모든 인스턴스가 동일한 기본 데이터를 공유하기 때문입니다.

성능 측면에서 인스턴싱은 특히 복잡한 씬이나 많은 수의 오브젝트를 다룰 때 복제보다 훨씬 효율적일 수 있습니다. 이는 인스턴싱이 각 인스턴스마다 새 데이터를 만들지 않으므로 복제보다 메모리를 덜 사용하기 때문입니다. 또한 인스턴싱은 Blender가 모든 인스턴스를 별도의 오브젝트가 아니라 하나의 오브젝트처럼 처리하여 렌더링 과정을 최적화하도록 할 수 있습니다.

전반적으로 인스턴싱은 Blender와 Decentraland 씬에서 성능과 작업 효율을 향상시키는 강력한 도구가 될 수 있으며, 특히 크고 복잡한 씬을 다룰 때 그렇습니다.

![](/docs/_remote/403e1a531d34d0b12ef576b8.webp)

나무, 식물, 가로등 기둥 같은 오브젝트를 복제할 때는, 어떤 경우에는 인스턴싱이 복제보다 성능을 크게 향상시킬 수 있습니다. 예를 들어 이 씬에는 14개의 가로등 기둥이 있고, 모두 완전히 동일합니다. 각 가로등 기둥에는 두 개의 서로 다른 텍스처가 있다는 것을 알고 있습니다. 하나는 기둥용이고, 다른 하나는 불빛용입니다. 따라서 이 경우 텍스처당 한 번씩, 총 두 번의 드로우 콜이 발생합니다.

![](/docs/_remote/b4811452757e72b24eb01716.webp)

Blender에서 요소를 복제하고 배치하는 단계에 있을 때는 세 가지 선택지가 있습니다. Duplicate, Instance 또는 Merge objects입니다.

각 절차의 장단점을 살펴보겠습니다.

### 오브젝트 복제

| 메뉴:  | Object ‣ Duplicate Objects |
| ---- | -------------------------- |
| 단축키: | Shift-D                    |

이렇게 하면 선택한 오브젝트와 시각적으로 동일한 복사본이 만들어지지만, 서로 다른 오브젝트로 처리됩니다. 따라서 내보내면 오브젝트당 드로우 콜이 2번씩 발생해 2 \* 14 = 28회의 드로우 콜이 되고, 디스크 사용량은 총 320kb가 됩니다.

![](/docs/_remote/4a2e11a5d69b78b82bfaeffb.webp)

### 오브젝트 인스턴싱

| 패널:  | Toolbar ‣ Tools ‣ Edit ‣ Duplicate Linked |
| ---- | ----------------------------------------- |
| 메뉴:  | Object ‣ Duplicate Linked                 |
| 단축키: | Alt-D                                     |

이렇게 하면 모든 데이터가 원본 오브젝트에 연결된 새 오브젝트가 생성됩니다. 연결된 오브젝트 중 하나를 편집 모드에서 수정하면, 연결된 모든 복사본이 수정됩니다. 변형 속성은 여전히 링크가 아니라 복사본이므로, 다른 복사본에 영향을 주지 않고 자유롭게 회전, 스케일, 이동할 수 있습니다.

![](/docs/_remote/2366fb1c01bf3e7b09b2e7f4.webp)

*이 모델들을 내보내면 드로우 콜 수는 여전히 28로 같습니다. 하지만 이제 메시가 하나뿐이므로 디스크 사용량이 크게 줄어듭니다(41 kb).*

![](/docs/_remote/8af76e55acae51d4209ab721.webp)

*정리를 위해 씬에서 컬렉션을 인스턴싱하는 것만으로도 충분합니다. 이렇게 하면 하나의 폴더와 소스에서 모든 인스턴스를 제어할 수 있습니다.*


> [!NOTE]
> **💡 팁**: 같은 논리가 SDK 측에도 적용됩니다. 모두 같은 `컴포넌트가 있거나, 아예 보이는 형태가 없는 엔티티에도` 파일을 가리키는 14개의 엔티티는 *.glb* 인스턴스처럼 동작합니다. 파일은 한 번만 다운로드되고, 한 번만 변환되며, 몇 개의 엔티티가 사용하든 메시와 텍스처는 메모리에 한 번만 유지됩니다. 같은 콘텐츠를 거의 동일한 14개의 *.glb* 파일로 나누는 것은 복제하는 것과 같아서, 다운로드 14번과 메모리상의 복사본 14개 비용이 듭니다.


### 오브젝트 병합

| 메뉴:  | Object ‣ Join |
| ---- | ------------- |
| 단축키: | Ctrl-J        |

선택한 오브젝트를 단일 메시를 가진 하나의 오브젝트로 합칩니다. Object Mode에서 작동하며, 마지막으로 선택한 *active* 오브젝트에 모든 것을 병합하고, 선택한 모든 오브젝트가 같은 유형이어야 합니다. 재질은 유지되고 병합되므로, 14개의 가로등 기둥은 더 이상 14개의 렌더 가능한 오브젝트가 아니라 하나가 되고, 엔진은 재질당 한 번씩, 총 2회의 드로우 콜로 이를 그립니다. 즉 28번 대신 2번입니다.

이것은 세 가지 옵션 중 실제로 드로우 콜을 줄이는 유일한 방법이며, 그 이유를 분명히 아는 것이 중요합니다. Decentraland 엔진은 스트리밍된 콘텐츠를 바탕으로 런타임에 씬을 구성하므로, 사전에 베이크된 콘텐츠처럼 반복되는 오브젝트를 대신 묶거나 배치할 수 없습니다. 드로우 콜을 줄여야 한다면 Blender에서 병합해야 합니다.

이 감소는 공짜가 아닙니다. 병합하면 여러 가지를 한꺼번에 포기하게 됩니다:

* **디스크 사용량이 다시 늘어납니다.** 병합된 메시에는 14개 기둥 모두의 기하 구조가 저장되므로, 인스턴싱으로 얻었던 절약 효과를 잃게 됩니다.
* **프러스텀 컬링이 전부 아니면 전무가 됩니다.** 병합된 오브젝트는 화면에 일부라도 보이면 전체가 그려집니다. 거리에 흩어져 있는 14개의 기둥은 거의 항상 하나는 보이게 되므로, 결국 항상 14개 모두를 그리게 됩니다. 이는 절약한 드로우 콜보다 더 큰 비용이 될 수 있습니다.
* **각 부분을 개별적으로 다룰 수 없게 됩니다.** 이제는 하나의 오브젝트만 남기 때문에, 개별 기둥 하나를 이동하거나, 애니메이션을 적용하거나, 클릭하거나, 숨길 수 없습니다.

병합은 제한적으로 사용하세요: 한곳에서 항상 함께 보이고, 상호작용이 없으며, 오브젝트 수가 실제로 성능을 저해한다는 것을 확인한 뒤에만 사용해야 합니다. 그 외의 모든 경우에는 인스턴싱이 더 나은 기본 선택입니다.


> [!WARNING]
> **📔 참고**: 14개의 개별 오브젝트를 하나의 *.glb* 파일로 내보내는 것은 **아니며** 병합입니다. 엔진은 여전히 14개의 오브젝트를 보고 28회의 드로우 콜을 발행합니다. 메시를 합쳐야만 개수가 바뀝니다.


## 메시 이름 지정

메시에는 의미 있는 이름을 사용하세요. 이름은 해당 에셋이 어디에 사용되는지, 또는 오브젝트의 어느 부분과 관련되는지에 대한 맥락을 제공해야 합니다.

에셋 이름 지정에는 다음을 조합해 사용하세요: `PascalCase` 및 `snake_case`, 이를 `PascalSnake_case`. 기본 규칙은 다음과 같습니다 - 새 단어 또는 구분자(`_`)로 시작합니다 **대문자입니다.**

* 메시에는 의미 있는 이름을 사용하세요 **예시:** 🟢 **다음을 사용하는 것을 권장합니다** 이름 - `극장`, `트램` 🔴 **피해야 할 것** 이름 - `Untitiled.008`, `primitive(1)`, `Cylinder.091`, `_sphere-AB`
* 언더스코어를 `_` 구분자로 사용해 이름에 더 많은 맥락을 더하세요. 더 일반적인 항목을 앞에 두고, 구체적인 내용은 뒤에 두세요. **예시:** 🟢 **다음을 사용하는 것을 권장합니다** 이름 - `분수조각상`, `극장메인벽`, `트램왼쪽바퀴` 🔴 **피해야 할 것** 이름 - `북쪽_메인벽_극장`, `트램_왼쪽앞_바퀴`

같은 이름의 오브젝트가 둘 이상 있으면 단어 뒤에 숫자를 붙이세요: `분수조각상01, 분수조각상02 등.`

## 모델 제작 도구

에셋을 만들 때 작업을 더 빠르고 효율적으로 만들어 주는 수많은 애드온과 외부 도구가 있습니다. 무료인 것도 있고 구매해야 하는 것도 있으며, 몇 가지를 들자면:

### Decimate

이것은 널리 알려진 모디파이어로, 모델의 표면 구조를 유지하면서 메시의 삼각형 수를 줄이는 데 사용할 수 있습니다. 모델 최적화에 매우 강력한 도구이지만, 모델을 디사이메이트하면 토폴로지가 영향을 받아 좋지 않은 토폴로지가 될 수 있다는 점을 유의해야 합니다(기하 구조를 예측할 수 없는 조각으로 분해하기 때문입니다). 또한 디사이메이션은 메시의 쿼드를 삼각형으로 바꾸어, 사용 후 수정하기 어렵게 만듭니다. 이런 점에서 **디사이메이션은 정적 모델에는 유용할 수 있지만 애니메이션 모델에는 선호되지 않습니다.**

![](/docs/_remote/5c1b597b93cffd4692e756c8.webp) ![](/docs/_remote/ffc83dd73f6105e78f5d4ed1.webp)

디사이메이션을 사용해 메시를 최적화하는 또 다른 방법은 모델을 디사이메이트한 뒤 적절한 리토폴로지를 하는 것입니다. 이렇게 하면 더 예측 가능한 결과와 깔끔한 토폴로지를 얻을 수 있습니다.

유용할 수 있는 리토폴로지 애드온은 다음과 같습니다(일부는 유료입니다):

* **Simplygon:** <https://www.simplygon.com/>
* **Speedretopo:** <https://blendermarket.com/products/speedretopo?ref=2>
* **Retopoflow:** <https://blendermarket.com/products/retopoflow>

### 미러 모디파이어

Blender의 미러 모디파이어는 오브젝트의 절반을 어떤 방향(X, Y, Z)으로든 대칭 복사해 대칭형 모델을 만드는 데 사용하는 도구입니다. 대칭형 모델을 다룰 때 매우 유용한 도구인데, 3D 모델링 시간과 UV 언래핑 시간을 줄여주고(모델의 한 부분만 언래핑하면 나머지는 같은 UV 좌표를 공유하기 때문), 텍스처 해상도를 사실상 대칭인 부분에 낭비하지 않도록 해 텍스처도 최적화해 줍니다.

![](/docs/_remote/d2acc97f8cfac981e2ef4ed3.webp)

### 일괄 이름 변경

이름 규칙을 쉽게 바꾸는 매우 편리한 도구는 Blender에 내장된 일괄 이름 변경 기능을 사용하는 것입니다. 사용하려면 *편집* 을 사용하고, 그다음 *일괄 이름 변경*.

![](/docs/_remote/b586dae5ffc349455527b2fc.webp)

이름을 바꾸려는 오브젝트를 선택한 다음 기본 오브젝트 이름을 새 이름으로 바꾸기만 하면 됩니다. 이 도구는 이름을 바꾸는 에셋의 종류와 방법을 다양하게 제공하므로, 메시, 애니메이션, 본 등도 매우 유연하게 이름을 변경할 수 있습니다.

## 기하 구조 모범 사례 [#](/docs/creator/3d-modeling/meshes/#best-practices-for-geometries)

* 3D 모델에 추가하는 면의 수를 신중하게 생각하세요. 면이 많을수록 렌더링 부담이 커집니다. 씬에 의해 부과되는 제한은 [**씬 제한 사항**](/docs/creator/sdk7/optimizing/scene-limitations/) 에서 확인하세요.
* 보이지 않지만 삼각형 수를 늘리는 숨은 면이 없는지 확인하세요.
* 둥근 면이 있어야 하는 형상은 면을 더 추가하는 대신 *부드럽게* 설정하세요.
* 모든 면의 *노말이* 안쪽이 아니라 바깥쪽을 향하도록 하세요. 렌더링했을 때 모델의 일부 면이 없는 것처럼 보인다면, 이것이 가장 가능성 높은 원인입니다.
* 메시의 회전과 스케일을 베이크해서, 바운딩 박스가 불필요하게 밖으로 뻗어나가지 않도록 하세요.
