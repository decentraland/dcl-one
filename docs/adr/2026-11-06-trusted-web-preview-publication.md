# ADR: Install trusted web preview publication independently

- Status: Proposed
- Date: 2026-11-06

## Decision

The trusted reviewer publisher runs on the default branch and consumes static artifacts produced by `Web previews / Build` for open same-repository pull requests. Application changes build with a read-only repository token and no publication credentials. Installing or updating the publisher is independent of merging those application changes.

Publication code and the dependency-free Figma key guard run from the trusted default-branch workflow commit. The guard and its allowlist keep their canonical `library/ui/figma/` paths, as defined by the [shared UI layout](2026-10-30-shared-ui-library.md); they require no UI package installation. Their source is unchanged from commit `8f27c6f68ac1d25a534f55edcf46e0266adec2ce`. The pull request contributes validated static files, with no lifecycle scripts executed by the publisher. Packaging rejects retired visual-comparison output before creating a package while preserving actual product icons and assets; approved mock imagery may use disclosed neutral placeholders, which does not establish a generic image-format ban.

Before installing dependencies or building, the unprivileged PR job validates the tracked Figma-source file digests and port record against the exact PR head and its merge base with the default branch. These dependency-free checks establish manifest and record structural consistency; the record is not a cryptographic attestation that its reported checks ran or its content was accepted. CODEOWNERS review and an independent Audit naming the exact source SHA supply the review authority.

The unprivileged PR job runs the source-owned functional checker against the built gallery under a nested version prefix. It checks catalog loading, component navigation, variant selection, a live component render with a nonzero box, runtime assets and page or console errors. The gallery publishes no visual-comparison interface, reference screenshots, render-difference images or fidelity report, and these checks make no claim of visual parity. The privileged publisher never runs the PR gallery, browser checker or other PR source.

The publisher requires a protected `web-preview` environment with explicit maintainer approval, administrator bypass disabled and only the default branch allowed. The source job validates its existence and protections before an approval job can be scheduled, so a missing environment cannot be automatically created by scheduling publication. The same validation runs after approval and immediately before publishing. A configured maintainer may approve their own source build. Publication revalidates the current PR, head, source run attempt, successful reviewer job and static artifact before sending the package to npm and requesting the CDN upload. A newer source build cancels stale approval waits. Approval requires a successful pending-comment job. A failed or cancelled pending-comment job is reported as a status-update failure, rather than publication ineligibility, and cannot release publication. A pending approval request also fails if the current status could not be posted because its source head, attempt or newest run changed. Eligibility rejects older meaningful same-head runs before approval and rechecks before packaging and publication; cancelled and timed-out builds can update status without becoming publishable. A pending comment replaces any older preview link before approval. After approved publication, the comment reports upload in progress, an expected duration of about 6-10 minutes and a link to the publication workflow in Actions for troubleshooting.

CDN readiness is the pipeline's successful GitHub deployment status for environment `cdn`, task `upload-to-cdn` and this package/version, following the existing Bevy rollout contract. The publisher does not poll the CDN while files are uploading. The reader-free `Web previews / CDN completion` workflow reads the source receipt, revalidates the current PR and source attempt, and checks the static HTML entry and version-scoped hashed bundle before posting a URL. Transient receipt and resource errors share a 60-second retry window after the success signal. Every CDN request sends an explicit preview User-Agent because the CDN rejects Python's default urllib signature. Completion retries verify the same deployed version and never publish another npm version. Comment writers share one serialized queue. Only a late upload-progress or waiting-for-approval update may reuse a prior canonical CDN URL after its fetched source receipt matches the current PR head, source run and attempt; the canonical comment body is reconstructed from trusted status data. Links from another run-derived package base are discarded before any receipt request. A transient receipt lookup failure leaves that call's existing comment unchanged and blocks dependent approval; a later ordinary diagnostic report can replace it with the explicit pending-status failure. Definite invalid or mismatched prior links are cleared. A comment marker or stored link alone supplies no authority. The completion script is checked out at its workflow commit. Oddish must keep the installed default-branch commit as its CDN deployment commit, because GitHub loads the completion workflow from that deployment commit; a PR merge tree without the installed workflow cannot start it.

The publisher requests npm package base version `0.1.<source_run_id>`. Oddish adds its timestamp and trusted publication-code commit suffix while keeping the installed default-branch workflow commit as the CDN deployment commit. The source receipt independently identifies the actual PR head, run and attempt.

Each CLI invocation shares a 180-second deadline measured as elapsed wallclock from CLI entry. CDN verification and local work consume this time too; the guard enforces the remaining budget before GitHub API requests and retry waits. Every request reserves up to 30 seconds; rate-limit retries wait at least 60 seconds and grow only when the remaining shared budget can accommodate both the delay and another request. Otherwise the command fails before sleeping or issuing that request. The same deadline applies through CDN verification and final status reporting, below the five-minute job timeout.

## Activation

Keep `WEB_PREVIEW_REVIEWER_ENABLED` disabled until this checklist is verified:

1. Install the trusted publisher, CDN completion workflow and scanner on the default branch after CI, CODEOWNERS review, independent Audit of the exact source SHA and the required merge authorization. Installing them does not publish a preview or replay earlier completed builds. Before activation, obtain the publication-environment decision, verify its protections and have the source-owned key-reader policy allow the exact publisher workflow, job and environment binding. The source key scan remains environment-free; an absent or disallowed publisher environment blocks activation.
2. Register `@dcl-regenesislabs/dcl-one-ui-review` in `definitions/src/static-site-rollouts.ts`, merge that definitions change and republish `@decentraland/definitions@next` for the upload pipeline to consume. An unregistered package can produce a successful pipeline that skips upload. Entries currently require domains; support for an entry serving only the CDN prefix is unverified and must be confirmed before activation.
3. Have an `@dcl-regenesislabs` owner publish an initial placeholder npm version `0.0.0`, then configure `npm trust` for repository `decentraland/dcl-one`, workflow `web-previews-publish.yml` and environment `web-preview`, with direct `npm publish` allowed. Keep npm `latest` and `next` absent or below `0.1.<source_run_id>` so Oddish does not override the requested base; publish previews only through custom `pr-N` tags without advancing `latest` or `next`. The package currently does not exist, so the trust configuration cannot yet be established. Verify this binding before enabling publication.
4. Verify the repository secret `FIGMA_FILE_KEY` is available to the trusted artifact scan and that the key check runs and passes. It is the file key used for leak detection; no environment-scoped Figma secret or `FIGMA_TOKEN` is required by the publisher. PR builds receive no Figma credentials and do not call the Figma API. The existing `GITLAB_CDN_DEPLOYER_TOKEN` and `GITLAB_CDN_DEPLOYER_URL` are shared organization secrets also used by Bevy previews; retain their existing consumers and verify that this repository can use them.
5. Verify that the GitLab upload pipeline pins `https://registry.npmjs.org` and rejects or ignores caller-provided alternate `REGISTRY_URL` values. Oddish passes that variable, and npm's environment-bound trust protects publishing only through the canonical registry. The source receipt identifies a build but does not authenticate its uploader. The shared CDN token and caller-supplied repository, commit and registry could otherwise publish arbitrary content with a matching receipt and have it linked as a preview. The GitLab-side registry policy is unverified and remains an activation blocker. GitHub runtime environment checks cannot attest to this policy or npm setup.
6. Enable `WEB_PREVIEW_REVIEWER_ENABLED`, re-run the current `Web previews / Build` for an open UI PR and approve its protected deployment. Confirm the pipeline creates the matching successful `cdn` / `upload-to-cdn` deployment, then the completion job posts the verified preview URL. Publication failures appear under Actions, `Web previews / Publish`; upload-verification failures appear under `Web previews / CDN completion`, rather than as checks on the source PR. If post-upload verification fails, retry that completion job to check the same deployed version. If upload fails or is skipped and no success status arrives, fix the upload configuration or pipeline failure, then re-run the Build; that path requires a new approval and publishes a new immutable npm version.

## Consequences

Publisher validation runs without publication credentials. UI build and hosting-base changes continue in their owning feature branches, including source-owned functional validation under a nested prefix before artifact upload. Static artifact validation rejects unsafe paths, links and unsupported files, and the trusted guard enforces file-count, byte-size and depth limits.

Published npm versions and CDN copies are public and immutable; closing a PR or expiring its GitHub artifacts does not remove them. Withdrawing published content requires the npm/CDN operators and verification that the affected URLs no longer serve it. This installation does not supply an SSR runtime for Sites.
