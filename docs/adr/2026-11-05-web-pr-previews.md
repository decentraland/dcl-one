# ADR: Independent web pull request previews

- Status: Proposed
- Date: 2026-11-05

## Decision

Preview selection follows the two web products: `apps/sites/` selects Sites and `library/ui/` selects the standalone UI reviewer. API-only changes do not trigger this preview pipeline. Changes to the preview pipeline select both products. Other application paths remain outside preview selection by owner decision; build dependency checks remain in the existing CI. Each PR update re-evaluates its cumulative diff, so a later documentation-only commit refreshes a preview selected by earlier web changes.

The UI reviewer is a static build published under an immutable versioned CDN path. Its assets, navigation, reference images and JSON requests must resolve inside that path. A successful product can publish independently of failures in the other product.

Pull request builds execute without publication credentials. Publication uses the trusted default-branch workflow and accepts only static reviewer output, with generated package metadata and no lifecycle scripts. Each publication requires human approval through a dedicated protected `web-preview` environment with administrator bypass disabled; publication code verifies that these protections and the exact default-branch deployment allowlist are configured. A pending comment precedes the approval wait, and newer publications cancel stale waits for the same PR. After approved publication, the comment reports upload in progress, an expected duration of about 6-10 minutes and an Actions link for troubleshooting. A configured maintainer may authorize publication of their own source build. It verifies the current open pull request, source repository, successful product job and artifact before publication. The CDN pipeline's successful `cdn` / `upload-to-cdn` deployment signals upload completion. A separate job then verifies the source receipt including run attempt, HTML entry, version-scoped hashed asset and fidelity JSON before reporting the preview link. CDN requests send an explicit User-Agent. Transient receipt and resource errors share a 60-second retry window. Retrying verification checks the same version without republishing. Serialized comment updates preserve an already verified URL for the same source run and attempt. Completion uses its workflow commit for the script checkout. Oddish must retain the installed default-branch deployment commit, because GitHub loads the completion workflow from that commit; a PR merge tree cannot provide the installed workflow. Reviewer publication stays disabled until the source CDN-base regression, audit and activation checklist pass, then the repository variable `WEB_PREVIEW_REVIEWER_ENABLED` enables it.

Sites retains server rendering, loaders and actions. Its preview uses a complete container image built from the pull request and runs in Kubernetes at a shared hostname supplied by deployment configuration. The initial preview is manually triggered and expires after six hours; it can be triggered again when needed. The infrastructure owner supplies the cluster configuration, and the application deployment integration remains to be agreed. Per-pull-request hosts are a possible later option with prorated cost. Services should default to development, with an explicit production selection; server and browser requests, caches and sessions must agree on that selection. The environment selector remains unimplemented.

## Activation

1. Install the trusted publisher and scanner on the default branch with publication disabled. Verify the protected `web-preview` environment requires approval, disables administrator bypass and allows only the default branch.
2. Register `@dcl-regenesislabs/dcl-one-ui-review` in `definitions/src/static-site-rollouts.ts`, merge the change and republish `@decentraland/definitions@next`. An unregistered package can be skipped by a successful upload pipeline. Entries require domains; support for an entry serving only the CDN prefix remains unverified.
3. Have an npm organization owner publish an initial placeholder version, then configure `npm trust` for this repository, `web-previews-publish.yml` and the `web-preview` environment with direct publishing allowed. Verify that the GitLab upload pipeline pins `https://registry.npmjs.org` and rejects or ignores alternate caller-supplied `REGISTRY_URL` values; this policy remains unverified. The receipt identifies a build but does not authenticate its uploader; a shared token and caller-selected registry could otherwise publish arbitrary content with a matching receipt.
4. Add `FIGMA_FILE_KEY` to `web-preview` and verify the trusted artifact key check runs and passes. Retain the shared organization-level `GITLAB_CDN_DEPLOYER_TOKEN` and `GITLAB_CDN_DEPLOYER_URL` used by Bevy and verify access; they do not need to be moved into the environment.
5. After all gates pass, enable publication and re-run the current open PR build. Approve the protected deployment, then verify the matching successful CDN upload produces the preview link. Failures appear under Actions, `Web previews / Publish`, rather than as checks on the source PR. Retry the completion job for the same version if post-upload verification fails. If upload fails or is skipped and no success status arrives, fix the upload configuration or pipeline failure, then re-run the Build; that requires a new approval and publishes a new immutable npm version.

## Consequences

Reviewer and Sites builds have independent artifacts and status rows. The build workflow provides an availability summary even before the publisher is installed on the default branch. Reviewer artifacts must pass a browser regression under a nested version prefix before upload; that regression checks component navigation, fidelity data and decoded reference/render images as well as asset delivery. API contract checks remain separate from preview selection.

Immutable npm versions and CDN copies remain after pull requests close; artifact retention does not delete published copies. Deployment status must distinguish a successful build from an available preview.

PR-built HTML and JavaScript are public and permanent on the shared CDN origin. A compromised dependency in a same-repository PR can alter that output; artifact validation and secret scanning do not establish content trust. Withdrawing published content requires the npm/CDN operators; expiring GitHub artifacts does not withdraw it.
