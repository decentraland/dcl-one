# Places outbox capture adapter

This opt-in pilot captures favorites for an immutable list of Genesis place UUIDs. Install only with the explicit operator command after reviewing the source DDL and role grants. It is not automatically installed when the worker starts. The target catalogue must already contain the same local place IDs. Shop, treasury and credits are excluded.

`places_outbox_v1` is a transactional outbox, not logical WAL decoding. Its monotonically committed transaction ordinals use the envelope's hexadecimal cursor representation; they must never be compared to PostgreSQL WAL LSNs. Source generation and adapter identity fence distinct capture histories. A restored/replaced source must receive a new reviewed generation and baseline before capture resumes; restoring the same generation and reusing positions cannot be treated as a safe failover.

A source-local BEFORE STATEMENT trigger serializes favorite mutations with a transaction advisory lock. Relevant rows and accepted command receipts share a transactional counter and commit atomically. Rollbacks consume no committed position. Internal SQL writes and deletes are captured even when they bypass HTTP. TRUNCATE is rejected because it cannot preserve this snapshot/capture contract. Disabling triggers, replacing the table, changing the capture schema, or bypassing triggers invalidates the pilot and requires stopping capture and a reviewed baseline.

Bootstrap takes that same source lock only while establishing a repeatable-read snapshot and its capture boundary, then releases it before exporting rows or contacting the target. The source pool needs at least two connections. It refuses an occupied destination scope and unsupported rows. Baseline export is bounded to 100,000 rows; transactions over the envelope limit stop capture instead of being truncated.

The installer needs DDL privileges on `public.user_favorites` and permission to create `migration_capture`. All functions run as the caller, not SECURITY DEFINER. The application role needs schema usage, function execution, SELECT on control/scope/transactions/receipts, UPDATE on control/transactions, INSERT on transactions/changes/receipts, and usage on the changes identity sequence, in addition to its existing business-table permissions. Review explicit grants for the actual deployment roles; the installer does not guess role names or grant public access.

The runtime source account needs only CONNECT, schema usage, and SELECT on capture tables and the source favorite/catalogue tables. It makes no source business writes and performs no source acknowledgements. Source history and receipts are retained; no automatic retention/pruning is implemented. Target capture progress advances only after the full envelope is durably stored. A crash between enqueue and progress update safely repeats the immutable envelope.

The serialization lock adds contention to all source favorite writes, including writes outside the scope. Rehearse latency and source storage growth before enabling it. This adapter is a bounded fallback for environments where logical CDC prerequisites are not established; it is not evidence that production capacity, privileges, retention, or failover have been verified.
