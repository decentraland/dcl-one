## Sources and states

Current baseline: dcl-one commit [1058d9a63](https://github.com/decentraland/dcl-one/commit/1058d9a6317a1394b91ef6ff3d483e384d9d16f4), with FDS revision `9c6dfbe61b2c218ff0b820841aac722df4ebd8aa` pinned in [upstream.lock.json](upstream.lock.json). Candidate source: [FDS component manifest at 5aa966b](https://github.com/decentraland/figma-design-system/blob/5aa966b6e965e07adbbd7f8d387184978390e4c3/dcl-ui-review/src/generated/components/manifest.ts). Local preview copies do not change the public package contract.

- **Public:** exported from [index.ts](index.ts), installed under `components/`, and recorded by [components/promotion.json](components/promotion.json). Read each component’s accepted limits before adoption.
- **Review only:** captured code exists under `figma/review/src/generated/`; applications must not import it.
- **Pending import:** present in the candidate source but absent from the current pinned review catalogue.
- **Blocked:** current `needsManual` entries or an explicit promotion gate remain unresolved. Candidate blockers are recorded separately and do not change current readiness.
- **Adopted:** an application imports the public contract and its consuming flow has been verified. Record consumer path, route, verification date/result and PR URL together.

## Using a component from an app

Load `@dcl/one-ui/foundations.css` once from the application global entry. Configure the source package and its CSS aliases in the application’s TypeScript and bundler setup, then import public components from `@dcl/one-ui`. The only current public generated component is NavBar, a limited bridge with the constraints listed in the [promotion registry](components/promotion.json) and [library README](README.md). The Explorer HUD currently consumes foundations; component adoption remains separate work.

Do not import from `figma/review/src/generated/` or a local preview copy. Promote and verify the component’s contract first, then replace one bounded app component and validate its interactions, accessibility, responsive behavior and consuming routes. Update this inventory in the same PR.

## Updating this inventory

The author of each import, promotion or application migration updates this tracked ledger in that same PR; reviewers check it against the package export, promotion registry and consuming code. For an import, record source revision, current and candidate identities, status and unresolved blockers. For app adoption, replace “Not recorded” with the consumer path, consuming route, verification date/result and full PR URL. Keep accepted limitations visible. A local copy, passing build or screenshot alone is insufficient evidence of app readiness.
